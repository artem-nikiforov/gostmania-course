Человек, с которым ты работаешь, может не знать внутренностей проекта — объясняй свои действия простым языком.

## 0. ГЛАВНОЕ ПРАВИЛО: Google Таблицы (аналитика)

В курсе есть **живая аналитика**: каждая попытка итогового теста отправляется в Google Таблицу
через Google Apps Script. Эта связка разорвана между тремя местами, и ломается **молча**
(курс продолжает работать, а данные просто перестают приходить).

### Обязательный протокол
Если задача хоть как-то затрагивает что-то из списка ниже — **СТОП**. Сначала предупреди человека
(явно, отдельным сообщением, до правок), объясни последствия, получи подтверждение, потом вноси
изменения и **веди человека по шагам** на стороне Google (агент не имеет доступа к его Google-аккаунту).

Триггеры — предупреждай, если задача касается:
- `TEST_QUESTIONS` (добавление/удаление/перестановка вопросов теста, изменение числа вопросов, текста вариантов ответов);
- функций `checkTest()`, `logTestAttempt()`, `initTest()`, `renderTest()`;
- констант `GOOGLE_SHEET_ENDPOINT`, `GOOGLE_SHEET_SECRET`, `TEST_PASS_RATIO`;
- ключей `sessionStorage`: `gostemania_test_attempt`, `gostemania_session_id`;
- SCORM-полей `student_id` / `student_name` (попадают в таблицу);
- файла `GOOGLE-SHEETS-LOGGING.md`;
- смены хостинга/домена, CSP, прокси, «политики безопасности» — всё, что может заблокировать запрос к `script.google.com`;
- нового теста, новой аналитики, новых полей для отправки;
- передачи проекта другому владельцу Google-аккаунта.

### Как устроена связка
```
js/app.js: checkTest() → logTestAttempt()
   └─ fetch POST (mode:'no-cors', text/plain, fire-and-forget)
        └─ Google Apps Script веб-приложение (URL заканчивается на /exec)
             └─ Google Таблица, лист «Ответы теста»
```
- Endpoint (URL `/exec`) и секрет `gostemania-2026` **вписаны прямо в `js/app.js`** (≈ строки 939–940)
  и лежат в git.
- Код Apps Script **НЕ хранится в репозитории как исполняемый файл.** Он живёт только в Google-аккаунте
  владельца (Таблица → Расширения → Apps Script). В репозитории лишь копия-образец в
  `GOOGLE-SHEETS-LOGGING.md`. Реальный скрипт может отличаться от копии — не считай копию истиной.
- Секрет `SHARED_SECRET` в Apps Script обязан **точно совпадать** с `GOOGLE_SHEET_SECRET` в `app.js`.
- Таблица и скрипт принадлежат аккаунту **владельца проекта**. Новый человек без доступа к этому
  аккаунту **не может** ни увидеть данные, ни изменить скрипт.

### Что ломает аналитику (и как это выглядит)
| Изменение | Результат |
|---|---|
| Изменили число вопросов теста (сейчас **10**) | Скрипт `FIELDS` знает только `q1…q10`. Вопросы №11+ **молча теряются**. Нужно править Apps Script **и** **заново разворачивать** (см. ниже) |
| Поменяли порядок/смысл вопросов | Колонки `qN` в таблице смешают старые и новые данные. Предложи человеку новый лист или пометку даты изменения |
| Изменили текст вариантов ответа | В колонку пишется **текст** ответа — история станет несравнимой со старой |
| Правка `app.js`, `GOOGLE_SHEET_ENDPOINT` стал пустым | Логирование **полностью выключено**, ошибок нет |
| Новое развёртывание Apps Script («Новое развёртывание», а не «Управление развёртываниями → Изменить → Новая версия») | **Меняется URL `/exec`** → старый URL в курсе перестаёт работать. Нужно обновить `GOOGLE_SHEET_ENDPOINT` и **пересобрать и перезалить SCORM-пакет в LMS** |
| Правка кода в редакторе Apps Script без нового деплоя | Изменения **не применяются** (работает старая версия) |
| Смена `SHARED_SECRET` только с одной стороны | Скрипт отвечает `forbidden`, данных нет, браузер ошибки **не покажет** (no-cors) |
| Закрытая корп. сеть / прокси режет `script.google.com` | Данные не доходят, пользователь ничего не замечает |
| Удалили/переименовали лист «Ответы теста» | Скрипт создаст новый пустой лист с тем же именем — старые данные останутся на старом |
| Правка Apps Script, меняющая порядок `FIELDS` | Новые строки не совпадут с заголовком и старыми данными |

### Если задача затрагивает аналитику — делай так
1. **Предупреди** человека: «Это затрагивает аналитику в Google Таблице. Вот что может сломаться: …».
2. Объясни, что изменения нужны **в двух местах**: код курса (я сделаю) и Apps Script в Google (делаете вы, я проведу по шагам).
3. Внеси правки в `js/app.js` и обнови `GOOGLE-SHEETS-LOGGING.md` (включая обновлённый код Apps Script — чтобы копия не устарела).
4. Дай человеку **точные пошаговые инструкции** для Google: что открыть, что вставить (готовый код целиком), какую кнопку нажать.
   Для обновления существующего деплоя: **Развернуть → Управление развёртываниями → ✏️ → Версия: Новая версия → Развернуть**
   (URL при этом **сохраняется**). «Новое развёртывание» — только если сознательно хотят новый URL.
5. **Попроси проверить:** пройти тест до конца и убедиться, что в таблице появилась строка с правильными колонками.
   Не говори «готово», пока человек не подтвердил, что строка пришла.
6. Если меняется `app.js` — напомни, что курс в LMS нужно **пересобрать (`scorm_pack.py`) и загрузить заново**; иначе у пользователей работает старая версия.
7. **Не меняй `no-cors`, fire-and-forget, `.catch(()=>{})` и обёртки try/catch** в `logTestAttempt()`.
   Это сделано намеренно: аналитика ни при каких условиях не должна блокировать или ломать прохождение курса.
   `logTestAttempt()` должен вызываться **последним шагом** в `checkTest()`.
8. Никогда не отправляй тестовые/выдуманные данные в боевой endpoint без явной просьбы — это загрязнит реальную аналитику.
   Для проверки лучше попросить человека создать тестовую копию таблицы и отдельный деплой.

### Безопасность аналитики (честно предупреди человека)
- URL endpoint и секрет лежат в открытом репозитории (GitHub). Проект на GitHub Pages публичный.
  Секрет — это не настоящая защита: любой, кто видит `app.js`, может слать данные в таблицу. Для внутреннего курса риск принят, но человеку об этом надо знать.
- В таблицу пишутся ФИО/ID сотрудников из LMS (`student_name`, `student_id`) — это персональные данные. Не выгружай их в чат, не копируй в репозиторий, не коммить экспорты таблицы.
- Не предлагай «улучшений» вроде убрать `no-cors` ради чтения ответа — это сломает отправку без preflight.

## 1. Что это за проект

Электронный курс для сотрудников (бренд-тематика Burger King Russia, внутреннее обучение) —
«Гостемания»: философия гостеприимства, алгоритм ДОБРО, работа с инцидентами, замена и комплимент, итоговый тест, заключение.
Язык интерфейса и контента — **русский**. Общайся с человеком по-русски.

Это **статический сайт без сборки**: vanilla JS, один HTML, Tailwind через CDN. Ни `package.json`, ни npm, ни фреймворков нет.
Курс доставляется как **SCORM 1.2 ZIP** в корпоративную LMS; параллельно есть публичная копия на GitHub Pages.

## 2. Структура

```
index.html            — всё приложение (SPA, ~1470 строк): страницы div.page, tailwind.config в <head>
css/style.css         — все стили, подключение шрифтов Flame
js/app.js             — роутер, все интерактивы, тест, прогресс, SCORM-вызовы, логирование в Google
scorm_pack.py         — упаковщик SCORM 1.2 (создаёт ZIP, генерирует imsmanifest.xml и scorm_api.js)
Fonts/                — шрифты Flame (OTF). Лицензионные — не выкладывать в публичные места лишний раз
images/, pictures/    — картинки (images/bite-seq/ — 61 кадр webp для scroll-анимации)
audio/, videos/       — mp3-диалоги и mp4
files/                — PDF-памятки (ГОСТЬ.pdf, ДОБРО.pdf)
DOCS.md               — архитектура и компоненты (местами устарел: упоминает 5 глав, сейчас 6 с тестом)
SCORM-NOTES.md        — как хранится прогресс и тонкости SCORM — ЧИТАТЬ перед правкой прогресса
GOOGLE-SHEETS-LOGGING.md — настройка аналитики (см. раздел 0)
.claude/              — локальные настройки агента (в .gitignore, не переносится через git)
course.zip            — собранный SCORM (в .gitignore, не переносится через git)
```

Страницы (`PAGES` в app.js): `home, block1, block2, block3, hub, section1, section2, section3, test, block8`.
Порядок глав: `CHAPTER_ORDER = ['block1','block2','block3','hub','test','block8']` — главы открываются последовательно;
«Заключение» (`block8`) открывается **только** после сдачи теста (порог `TEST_PASS_RATIO = 0.8`).
Нумерация блоков в id перескакивает (нет «блока 4») — это историческое, не «исправляй».

## 3. Запуск и проверка

```bash
cd <папка проекта>
python3 -m http.server 3333      # открыть http://localhost:3333
```
Тестов и линтера нет — проверяй вручную в браузере. Требует интернета (Tailwind CDN, Google Fonts).
Сброс прогресса: в консоли `localStorage.removeItem('gostemania_progress')` и перезагрузка.
Внимание: прохождение теста на localhost **отправляет реальные данные в боевую таблицу** (endpoint вписан в код).
Перед тестированием теста предупреди человека (см. п. 0.8) или временно очисти `GOOGLE_SHEET_ENDPOINT` локально — и **не коммить** эту очистку.

## 4. SCORM и сборка пакета

- Запуск: `python3 scorm_pack.py` → создаёт ZIP рядом со скриптом. **Имя ZIP и `course_id` берутся из имени папки проекта** (`slugify`, только ASCII).
  Для папки «Курс Гостемания» кириллица отбрасывается → идентификатор `course`, файл `course.zip`.
  **Не переименовывай папку проекта без необходимости**: изменится идентификатор в манифесте, LMS может посчитать пакет другим курсом и потерять прогресс пользователей.
  Если на новом компьютере папка называется иначе — предупреди человека и согласуй, какой `course_id` нужен в LMS.
- `scorm_api.js` **не лежит в репозитории** — он генерируется упаковщиком и вставляется в ZIP. В `index.html` на диске подключения нет. Не добавляй его руками.
- Все вызовы `SCORM.*` в app.js обёрнуты в `if (window.SCORM ...)` — вне LMS объекта нет. **Не убирай эти проверки.**
- Прогресс: SCORM `cmi.suspend_data` (лимит ~4096 символов) + запасной `localStorage['gostemania_progress']`.
  Восстановление — на `window.load`, не `DOMContentLoaded`. После `set` обязателен `commit`.
- Статус «пройдено» ставит только кнопка «Завершить курс» (`SCORM.complete()`). Не понижай уже зачтённый статус.
- После **любой** правки контента/кода курса, который должен дойти до пользователей LMS, нужно пересобрать ZIP и загрузить в LMS заново. Пуш в git LMS-версию **не обновляет**.
- `course.zip` в `.gitignore` — собери его заново на новом компьютере.
- Видео вставлены iframe с внутреннего видеохостинга `bktube.burgerkingrus.ru` — доступны **только из корпоративной сети/VPN**. Вне её плееры не загрузятся — это не баг.

## 5. Git и деплой

- Ветка `main`. Два remote: `origin` → GitHub (`artem-nikiforov/gostmania-course`, публикуется на GitHub Pages: `https://artem-nikiforov.github.io/gostmania-course/`),
  `gitlab` → внутренний GitLab компании (`gitlab.burgerkingrus.ru/Artem.Nikiforov/d.learning`).
- **Пуш в `origin/main` = публикация на публичный сайт** (~1 мин). Не пушь и не коммить без явной просьбы человека.
- На другом компьютере у человека другие учётные данные: нет доступа к remote'ам ≠ ошибка кода. Не пытайся «обходить» авторизацию.
  Если нужно — предложи сменить `origin` на свой репозиторий. **Не удаляй и не перезаписывай remote'ы без согласования.**
- Все пути в HTML/JS — **относительные** (`images/...`, не `/images/...`), иначе GitHub Pages (сайт в подпапке) сломается.
- Не делай `git push --force`, `git reset --hard`, `git clean` без явного подтверждения.
- Не коммить: `.DS_Store`, `*.zip`, `.claude/`, выгрузки данных из таблицы.

## 6. Тонкие места кода

- Тест перемешивает варианты ответов на каждую попытку (`shuffledIndices`), но в таблицу пишется **текст** выбранных вариантов. Правка текста варианта = см. п. 0.
- Номер попытки (`attempt`) считается в `sessionStorage` вкладки — он **не** глобальный по пользователю. Не рассчитывай на него как на «общее число попыток».
- Перед правкой навигации учти: `navigateTo()` ставит паузу медиа (`stopMediaIn`) и вызывает инициализаторы страниц (`initGallery`, `initSortable`, `initVideoQuiz`, `initHubWarmup`, `initTest` и т. п.).
- Хаб (`hub`): 3 подраздела разблокируются последовательно (`hubDone`). Состояние пишется в прогресс.
- Drag-and-drop, matching, scroll-story (`images/bite-seq`) — самописные; ломаются от переименования id/классов. При правке HTML сверяй id с app.js (grep).
- `index.html` ≈ 100 КБ в одном файле: правь точечно (Edit), не перезаписывай файл целиком.
- Tailwind конфиг с цветами бренда — внутри `<head>` index.html; палитра описана в DOCS.md.
- Не меняй нейтральные fallback'ы картинок (`onerror`) и относительные пути медиа.

## 8. Перенос на новый компьютер — чек-лист для агента

При первом запуске на новом месте проверь вместе с человеком:
1. `git status`, `git remote -v`, `git log -3` — репозиторий на месте и история не потеряна.
2. Есть ли доступ к remote'ам и под каким аккаунтом человек пушит.
3. Установлен Python 3 (нужен для `scorm_pack.py` и локального сервера).
4. Есть ли интернет и доступ к VPN (видео bktube, CDN).
5. **Аналитика:** у человека есть доступ к Google-аккаунту владельца таблицы/скрипта? Если нет — предупреди (п. 0): менять скрипт, смотреть данные и перевыпускать endpoint он не сможет. Либо владелец дает доступ к таблице («Редактор»), либо создаётся новая таблица + новый скрипт + новый URL в `app.js` (по `GOOGLE-SHEETS-LOGGING.md`), и тогда старые данные остаются у владельца.
6. Собрать `python3 scorm_pack.py` и убедиться, что ZIP создаётся, имя и `course_id` ожидаемые.
7. Нет ли папок `.claude/`, `course.zip` — они не переносятся через git; это нормально, создаются заново.
